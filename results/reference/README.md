# Reference outputs

Compact reference material for the final report. This directory is the only part
of `results/` that is committed.

## What this is, and what it is not

- These are **reference outputs**, not the complete experimental record.
- The reported experiments were run on the **full measurement datasets**
  (roughly 100 MB of per-process Parquet across four workload runs, and a
  separate 18-phase controlled dataset). Neither is committed here.
- `datasets/demo/` holds a small real-data subset used **only** to demonstrate
  that the repository executes end to end after cloning. It does **not**
  reproduce the numbers in the report.
- Everything the experiment scripts generate at runtime (`results/moe/`,
  `results/feature_moe/`, `results/offloading/`, `results/demo/`) is ignored by
  Git and is recreated by running the commands in the top-level `README.md`.

## Contents

| File | Report component | Produced by |
|---|---|---|
| `learned_feature_moe_final_summary.md` | Controlled resource-MoE evaluation — phase-level LORO (18 folds) and group-level LOGO (4 folds) | `experiments/run_learned_feature_moe_final.py`, run on `data/controlled_workload_labeled_final.parquet` |

The LORO/LOGO summary is a copy; the original remains at
`feature_moe/learned_feature_moe_final_summary.md`, next to the implementation
it documents.

Its companion per-fold outputs (`learned_feature_moe_phase_loro_metrics.csv`,
`learned_feature_moe_group_logo_metrics.csv`, the two gate-weight tables, and
`learned_feature_moe_hyperparams.csv`) are not present in this repository. They
are regenerated by re-running the script above against the controlled dataset,
which is external to this submission.
